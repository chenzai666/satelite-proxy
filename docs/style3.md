## 整体风格定位

这套界面可以概括为：

**macOS 原生框架感 + 太空叙事 + 复古终端仪表 + 低对比暗色玻璃质感**

它没有完全照搬 macOS 系统组件，而是保留系统窗口、菜单栏弹窗、圆角和浮层逻辑，再加入明显的品牌化视觉语言。整体气质偏：

* 安静、克制
* 专业、精密
* 带有少量科幻感
* 兼具工具属性和观赏性
* 类似“系统维护控制台”与“太空任务中心”的结合

---

## 1. 核心视觉概念：用天体表达系统状态

界面最有辨识度的部分是天体隐喻：

* **Clean 页面：地球**
* **Optimize 进行中：月球或未知星球**
* **Status 健康状态：太阳**
* **完成清理：Return to Earth**

这些元素让枯燥的系统维护过程拥有了一套完整叙事：

* 清理磁盘类似整理地球环境
* 深度优化类似进入太空执行任务
* 健康评分通过太阳表达能量和稳定状态
* 操作结束后“返回地球”

这种设计的优势是品牌记忆非常强。用户记住的会是“那个有星球的清理软件”，而非普通的系统清理工具。

同时，天体材质偏真实，没有使用卡通插画，因此仍然保留专业感。

---

## 2. 窗口与整体构图

### 大窗口

主窗口采用宽屏悬浮结构：

* 接近 16:10 的窗口比例
* 大圆角外框
* 很窄的系统标题栏区域
* 背景壁纸在窗口四周露出
* 深色窗口与明亮桌面形成明显分层
* 窗口阴影宽且柔和

窗口本身类似一块悬浮在桌面上的控制面板。

页面边缘几乎没有传统侧边栏，也没有厚重工具栏，主要内容集中在中间区域。这让应用显得轻盈，同时强化了沉浸感。

### 留白策略

Clean 和 Optimize 页面使用大量负空间：

* 顶部只有导航
* 中间放置天体
* 下方放置状态信息
* 辅助内容压缩到较小区域

这种布局会让核心操作显得重要，也能降低清理软件常见的“广告工具箱”感。

## 3. 顶部导航设计

顶部导航是整套界面的重要视觉锚点。

### 结构

采用水平胶囊形导航：

```text
Logo | Clean | Apps | Optimize | Analyze | Status
```

特点包括：

* 整体悬浮在页面顶部中央
* Logo 与导航融为一个组件
* 激活项使用白色胶囊背景
* 非激活项使用低亮度文字
* 导航区域有轻微半透明和内阴影
* 宽度控制得很紧凑

这比传统 macOS 工具栏更具品牌特征，同时仍然符合 segmented control 的操作习惯。

### 优点

* 当前页面状态十分明确
* 视觉重量较轻
* 不占用窗口两侧空间
* 页面内容能够自由切换宽屏布局
* 很适合功能数量固定的工具软件

### 潜在问题

导航使用等宽字体，字重较高，较小尺寸下会略显粗糙。激活项的白色对比非常高，容易抢走天体主体的部分注意力。

更合理的处理可以是：

* 激活背景改为略带页面主题色的浅灰
* 非激活文字提高少量亮度
* 导航栏整体缩小约 5%～8%
* Logo 与第一个导航项增加一点间距

## 4. 色彩系统

### 基础背景

主要使用两套深色背景：

#### 蓝色主题

用于 Clean 页面：

* 深海军蓝
* 靛蓝
* 接近黑色的底部渐变

给人的感受是干净、冷静、可信，适合清理、扫描和完成状态。

#### 暖棕主题

用于 Optimize 和 Status：

* 深橄榄棕
* 黑褐色
* 轻微金色雾化效果

它强化了复古航天设备和老式终端的感觉。

### 功能色

界面没有依赖单一品牌色，而是按数据类型分配颜色：

* 绿色：健康、CPU、完成状态
* 蓝色：磁盘、网络
* 黄色：GPU、风扇、优化进度
* 青色：温度、连接状态
* 白色：主要结果和关键操作

功能色饱和度很低，更像仪器指示灯，避免了常见仪表盘中过于花哨的彩虹配色。

### 色彩问题

部分暖棕页面存在轻微“发灰、发脏”的感觉，尤其在低亮度显示器上：

* 卡片与背景差异较小
* 黄色文字对比度偏低
* 边框容易融入背景
* 表格辅助文字阅读压力较高

建议保持暖色氛围，同时降低棕色覆盖量，让背景更接近中性黑灰，暖色集中在光晕、边框和状态标签中。

## 5. 字体与排版

这套界面使用了两类字体语言。

### 大标题与结果数字

采用圆润的无衬线字体：

* `86.4 GB`
* `Deep-optimizing your system`
* `100`
* `91%`

特点是粗、清晰、现代，负责传达主要状态。

### 导航、标签与数据

大量使用等宽字体：

* 导航文字
* 设备型号
* 系统版本
* 进程信息
* CPU、内存数据
* 辅助说明

等宽字体带来终端、开发工具、系统监控器的气质。

### 排版层级

大致层级如下：

| 层级 | 用途          | 特征         |
| -- | ----------- | ---------- |
| 一级 | 结果、健康分、主要状态 | 粗体，大字号     |
| 二级 | 卡片数值、标题     | 中等字号，较高对比  |
| 三级 | 标签、设备信息     | 等宽字体，彩色或灰色 |
| 四级 | 描述、单位、时间    | 小字号，低对比    |

整体排版统一，但小字号偏多。菜单栏弹窗中的进程信息、磁盘说明和底部统计，在普通 Retina 显示器上仍可阅读，缩放或非 Retina 环境下会比较吃力。

## 6. Clean / Optimize 页面分析

这两页属于“沉浸式任务页面”。

### 页面结构

```text
顶部导航

天体主视觉

主要标题或结果

状态描述

按钮或任务详情
```

### 优点

* 用户注意力集中
* 扫描和等待过程更有仪式感
* 页面状态转换很容易做动画
* 能显著提高产品质感
* 避免传统进度条带来的廉价感

### Optimize 页面

进行中页面使用月球作为中心视觉，下方显示：

* 当前阶段
* 任务编号，例如 10/23
* 已完成项目列表
* 当前执行项目

任务列表使用暗色半透明面板，存在较强的命令行日志感。

这里的体验重点是“系统正在执行复杂操作”，因此细节信息有助于建立可信度。

### Clean 完成页面

完成页面只保留：

* 地球
* 清理结果
* 等价的视频时长
* 累计清理量
* Return to Earth 按钮

信息控制得很克制，完成感较强。

按钮使用描边形式，视觉权重偏弱。若用户完成后还需要返回、查看详情或继续操作，建议增加一个更明确的主按钮状态，例如浅色半透明填充。

## 7. Status 页面分析

Status 页转为高密度仪表盘布局。

### 顶部卡片区

采用两行四列卡片：

* Health
* CPU
* GPU
* Memory
* Battery
* Disk
* Network
* Fan

每张卡片结构基本统一：

```text
图标 + 模块标题 + 状态标签
核心数字
图表或控制组件
辅助说明
```

卡片圆角适中，边框极淡，背景只有很小的明度变化。它们更像一体化仪表盘中的分区，而非独立浮动卡片。

### Health 卡片

Health 卡片面积最大，内容包括：

* 健康评分
* 评级
* 检查状态
* 运行时间
* 太阳图形
* 设备型号和系统版本

太阳图形兼具装饰和状态象征，使整个状态页与前面的天体主题保持联系。

### 数据卡片

CPU、GPU、内存、网络使用微型图表：

* 没有复杂坐标轴
* 只表达趋势
* 线条或柱形数量少
* 图表颜色与模块标签一致

这种设计适合概览，不适合深入诊断。界面定位明显偏日常状态检查。

### 风扇卡片

风扇卡片同时包含：

* RPM
* 负载
* Auto / Cool / Max 模式
* 系统管理状态

它比其他卡片具有更强的交互属性，因此视觉结构略拥挤。模式选择按钮与数据图表的表现形式相近，用户可能需要短暂判断哪些元素可点击。

建议提高控制区域的容器感，或者增加 hover 与选中状态差异。

## 8. 进程表格

底部使用完整宽度的进程列表：

* 应用图标
* 进程名称
* PID
* CPU
* 功耗
* 内存
* 更多操作

表格保留了 macOS 活动监视器的熟悉结构，但视觉上更加柔和。

### 设计亮点

* CPU 使用条嵌入数值列
* 行距适中
* 图标尺寸克制
* 表头对比度很低
* 分割线细且透明
* 高消耗进程容易快速定位

### 可优化点

表格区域与上方卡片之间的区分较弱，容易形成一整块深色内容。可以增加：

* 表格标题栏
* 搜索或筛选入口
* 高消耗进程快速过滤
* 表头更明确的排序状态
* hover 行背景
* 当前异常进程的语义颜色

---

## 9. 菜单栏弹窗

菜单栏版本相当于 Status 页的压缩形态。

### 结构

狭长浮窗中包含：

* 总体健康评分
* 设备概况
* CPU / GPU
* 内存 / 磁盘
* 网络 / 风扇
* 电池
* 进程排行
* 快捷操作
* 累计清理数据

它与主窗口共用：

* 同一套暖棕背景
* 同一套功能色
* 同一种等宽字体
* 同一套圆角卡片
* 同一种数据图表

这体现了很强的设计系统意识。菜单栏组件没有重新设计成另一套风格，而是将主界面模块化压缩。

### 问题

信息量接近一个完整应用页面，弹窗宽度却比较有限：

* 字号较小
* 模块间距紧
* 标签较多
* 进程名称被频繁截断
* 底部 Clean Watch 统计稍显拥挤

可以将默认弹窗控制在三个层级：

1. 健康评分和核心告警
2. CPU、内存、网络、电池
3. 查看全部状态入口

进程排行和累计数据可以折叠或进入二级页面。

## 10. 组件语言

整套 UI 的组件特征十分统一：

### 圆角

* 主窗口：约 22–26px
* 顶部导航：完整胶囊
* 数据卡片：约 14–18px
* 标签：约 4–6px
* 按钮：胶囊形

### 边框

* 1px 半透明浅色边框
* 对比度很低
* 部分组件带轻微内高光
* 几乎没有硬分割线

### 阴影

* 主窗口阴影宽且柔和
* 卡片内部很少使用明显阴影
* 依靠色差、边框和渐变建立层级

### 背景材质

虽然看起来有玻璃感，但透明度并不高，更接近：

**磨砂玻璃表面覆盖一层深色实体材质**

这种处理可避免背景壁纸干扰数据阅读。

## 11. 动效推测

静态截图已经为动效预留了很大的表现空间，适合使用：

* 星球缓慢自转
* 清理时表面逐渐变亮
* 优化阶段切换天体
* 卡片数据平滑更新
* 微型图表连续滚动
* 导航胶囊滑动切换
* 健康分数递增动画
* 操作完成后轻微光晕扩散
* 菜单栏弹窗展开时卡片顺序淡入

动效速度应保持缓慢，避免接近游戏 HUD。大部分状态动画控制在 200–400ms，天体动画可以持续数十秒。

## 12. 设计优势

### 品牌识别度强

天体主题、暖棕终端色、胶囊导航共同形成独特外观，辨识度远高于常见系统工具。

### 页面层级清楚

任务页使用沉浸式单焦点布局，状态页使用高密度数据布局，页面目的明确。

### 专业感和亲和感平衡较好

等宽字体、系统数据和进程表格提供专业感；圆角、柔和渐变和天体图形降低了工具软件的冷硬感。

### 主窗口与菜单栏高度一致

组件能够在不同尺寸下复用，说明设计系统具备较强延展性。

### 广告感很弱

没有大型推荐卡片、促销 Banner、夸张警告色，整体更接近付费精品工具。

---

## 13. 主要问题

### 低对比度较严重

暖棕色背景中，次级文字、边框、图表和卡片背景差异过小。长时间使用容易产生阅读疲劳。

### 内容密度差异明显

Clean 页面非常空旷，Status 页面非常密集，页面切换时会有较明显的视觉跳跃。

### 天体占用大量面积

天体对品牌塑造很有效，但实际操作频繁后，用户可能更关心数据和操作效率。可以提供紧凑模式，缩小主视觉。

### 控件状态辨识度不足

部分分段按钮、标签、图表和状态块采用相似视觉表现，可点击区域不够直观。

### 数据语义略模糊

例如 Health 100、Pressure 18%、Load 0% 等指标需要明确解释。缺乏说明时，用户容易将这些数字理解为营销评分。

### 菜单栏弹窗负担较高

内容量较大，适合展示能力，但日常查看效率还有压缩空间。

```text
卡片边框：rgba(255,255,255,0.07–0.11)

主文字：rgba(255,255,255,0.92)
次级文字：rgba(255,255,255,0.55)
弱文字：rgba(255,255,255,0.32)

健康绿：#55C89A
磁盘蓝：#6597DB
网络青：#4DA7BE
状态黄：#C6A25F
警告橙：#D68B58
```

### 圆角

```text
窗口：24px
大卡片：16px
小卡片：12px
输入框：10px
标签：5px
主按钮：999px
```

### 间距

建议使用 8px 基础网格：

```text
卡片内边距：16 / 20px
卡片间距：12 / 16px
页面边距：16 / 24px
顶部导航与内容：24 / 32px
```

### 字体

```text
标题：系统无衬线字体，600–700
结果数字：系统无衬线字体，650–750
模块标签：等宽字体，600
数据说明：等宽字体，400–500
```

## 15. 风格总结

这套设计的核心价值并不在复杂特效，而在于建立了一套完整且统一的产品世界观：

* 天体负责情绪与品牌
* 等宽字体负责技术感
* 卡片仪表负责信息组织
* 暗色磨砂材质负责高级感
* 胶囊导航负责简洁和友好
* 低饱和功能色负责状态表达

它很适合系统优化、代理工具、网络监控、开发者工具、设备管理等桌面软件。用于你的代理软件时，星球可以替换为节点网络、卫星轨道或地球连接状态，Status 卡片系统也能直接映射为延迟、流量、连接数、内存、核心状态和出口节点。
